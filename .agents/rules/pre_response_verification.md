# 🛡️ Mandatory Pre-Response Verification Rule (กฎการตรวจสอบความถูกต้องก่อนตอบทุกครั้ง)

> **CRITICAL DIRECTIVE / คำสั่งบังคับเด็ดขาด**:
> ก่อนส่งข้อความตอบกลับ สรุปผล หรือรายงานผลใดๆ ให้กับผู้ใช้งาน **ต้องทำการตรวจสอบคำตอบและค้นหาข้อผิดพลาดในงานที่ทำไปทุกครั้งอย่างละเอียด (Double-Check & Error Detection)** เพื่อป้องกันความผิดพลาดในทุกขั้นตอน

---

## 📋 Checklist การตรวจสอบก่อนตอบ (Pre-Response Verification Checklist)

1. **🔍 ตรวจสอบความถูกต้องของการทำงานจริง (Runtime & Execution Check)**:
   - ตรวจสอบว่าโค้ด, คำสั่ง, API endpoints, หรือ Manifests ที่เพิ่งแก้ไข ได้รับการทดสอบหรือ verify จริงบน environment/server แล้วหรือไม่
   - ตรวจสอบว่าผลลัพธ์ที่ได้ตรงตามความคาดหวัง ไม่มีการเกิด error ซ่อนเร้น (Silent Failures, Syntax Errors, หรือ Exception หลุดรอด)

2. **🌐 ตรวจสอบความถูกต้องของเครือข่ายและเส้นทาง (Network, Ports & Gateway Rules)**:
   - ตรวจสอบว่าเส้นทาง (URLs, Endpoints, Host Headers, Traefik/Ingress Routes, Port Mappings) ถูกต้องตรงตามสถาปัตยกรรมที่กำหนด
   - ต้องมั่นใจว่าไม่มีการอ้างอิงพอร์ตหรือเส้นทางที่ bypass ระบบ หรือขัดแย้งกับข้อกำหนดของผู้ใช้ (เช่น การบังคับวิ่งผ่าน Traefik Gateway เท่านั้น)

3. **📝 ตรวจสอบความสอดคล้องของคำตอบกับความจริง (Grounding & Fact Verification)**:
   - ห้ามคาดเดาผลลัพธ์หรือสรุปผลล่วงหน้าโดยไม่มีหลักฐานยืนยันจากการรันคำสั่งหรืออ่านไฟล์จริง
   - ตรวจสอบข้อมูล ตัวเลข สถานะ และชื่อตัวแปร/บริการว่าตรงกับสภาพจริง 100%

4. **🔄 หากพบข้อผิดพลาดระหว่างตรวจทาน (Error Correction Protocol)**:
   - หากตรวจพบจุดผิดพลาด ข้อขัดแย้ง หรือข้อมูลที่ไม่ตรงกับความจริง ต้องรีบแก้ไขให้เรียบร้อยและทดสอบซ้ำจนมั่นใจ ก่อนที่จะตอบกลับผู้ใช้งานเสมอ
